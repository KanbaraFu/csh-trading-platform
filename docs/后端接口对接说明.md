# 后端接口对接说明（淘学二手 · 校园二手交易平台）

> 用途：交给后端同学实现 `/api/**` 时的对接契约。
> 来源：完全对齐前端 `src/api/*.js` 的调用方式与 `src/mock/modules/*` 的字段实现，**字段命名一律 `snake_case`**。
> 权威参考：`src/mock/handlers.js`（路由表）+ `src/mock/modules/*`（入参/返回实现）。
>
> ⚠️ **路径基准**：本仓库为 monorepo，本文档中所有 `src/**` 路径均指 **`frontend/src/**`**（前端已迁入 `frontend/` 目录）。

---

## 一、通用约定（**必须先对齐，否则前端全部不可用**）

### 1.1 基础信息

| 项 | 值 |
|---|---|
| 后端地址 | `http://localhost:8080`（开发期由 Vite 代理，见 `vite.config.js`） |
| 统一前缀 | `/api`（前端 `baseURL = '/api'`） |
| 超时 | 12 秒（`axios` 配置） |
| 请求/响应 | JSON，`Content-Type: application/json` |

### 1.2 统一响应结构（铁律 1）

```json
{ "code": 200, "message": "success", "data": {} }
```

| code | 前端行为 |
|------|---------|
| `200` | 成功，前端取 `data` |
| `401` | **清空登录态并跳转登录页**（`AppLayout.vue` 的 `setUnauthorizedHandler`） |
| 其他 | 弹出 `message` 提示并 reject |

> **注意**：`message` 会被**直接展示给用户**，请写中文可读文案（如"密码错误，请重新输入"）。
> 前端 `unwrap()` 对没有 `code` 字段的响应会原样返回，但**请统一返回上述结构**，不要返回裸对象。

### 1.3 鉴权（铁律 2）

前端请求拦截器：

```js
service.interceptors.request.use((config) => {
  const token = localStorage.getItem('campus_token')
  if (token) config.headers.token = token   // ← 请求头名为 token
  return config
})
```

> ⚠️ **后端必须读取名为 `token` 的请求头**，**不是** `Authorization`、也不是 `Bearer token`。
> 这是最容易踩的坑，务必确认。

### 1.4 分页结构（铁律 3）

```json
{ "records": [], "total": 0, "pageNum": 1, "pageSize": 10 }
```

| 字段 | 含义 |
|------|------|
| `records` | 当前页数据数组（**不是** `list` / `items` / `rows`） |
| `total` | 总条数 |
| `pageNum` | 当前页码 |
| `pageSize` | 每页条数 |

**部分接口的额外字段**（见各接口说明）：
- `GET /orders` → 额外返回 `counts`（各状态数量）
- `GET /addresses` → 返回 `{ records, selected_id }`（**非标准分页**）
- `GET /cart` → 返回汇总对象（**非分页**）
- `GET /messages` → 额外返回 `counts`

### 1.5 时间格式

统一 `'YYYY-MM-DD HH:mm:ss'` 字符串，例如 `2026-09-15 14:30:00`。

### 1.6 登录态约定

| 存储键 | 说明 |
|--------|------|
| `campus_token` | 登录令牌（前端请求头 `token` 的来源） |
| `campus_user_id` | 当前用户 ID（前端路由守卫鉴权依据） |

登录/注册成功后，前端会把 `token` 与 `user.id` 写入 localStorage 并据此判断登录态。

## 二、通用数据结构

### 2.1 Product（商品，`decorateProduct` 装饰后）

原始字段 + 装饰字段（前端列表/详情**直接使用装饰后的字段**，后端需一并返回）：

```json
{
  "id": 1,
  "seller_id": 1,
  "category_id": 2,
  "title": "……",
  "description": "……",
  "price": 99.00,
  "original_price": 199.00,
  "stock": 1,
  "cover": "https://……",
  "status": 1,
  "view_count": 120,
  "sales_count": 3,
  "condition": "九成新",
  "location": "校内可送达",
  "create_time": "2026-09-01 10:00:00",
  "update_time": "2026-09-02 10:00:00",

  "images": ["https://……", "https://……"],
  "seller_nickname": "林小满",
  "seller_avatar": "https://……",
  "seller_college": "计算机科学与技术学院",
  "category_name": "数码电子",
  "is_available": true
}
```

| 装饰字段 | 计算规则 |
|---------|---------|
| `images` | 商品图片列表（按 `sort` 升序）；为空时回退为 `[cover]` |
| `seller_nickname` / `seller_avatar` / `seller_college` | 关联卖家信息 |
| `category_name` | 关联分类名称 |
| `is_available` | `status === 1 && stock > 0` |

**`status` 取值**：`0` 已下架 / `1` 在售 / `2` 已售出（库存为 0 时置 2）

## 三、接口明细

> 标注 **🔒** 的接口需要携带 `token` 请求头，未登录返回 `code: 401`。

### A. 用户与认证

#### POST `/auth/captcha` — 发送验证码

| 入参 | 类型 | 说明 |
|------|------|------|
| `phone` | string | 11 位手机号，正则 `/^1\d{10}$/` |

返回：
```json
{ "phone": "13800000001", "code": "123456", "expireSeconds": 300 }
```
> 演示环境直接返回验证码；生产环境应改为真实短信下发。

#### POST `/auth/register` — 注册

| 入参 | 类型 | 说明 |
|------|------|------|
| `phone` | string | 手机号 |
| `password` | string | 至少 6 位 |
| `code` | string | 验证码 |
| `nickname` | string | 可选，默认 `同学{手机号后4位}` |

返回：`{ "token": "…", "user": { /* 用户信息（不含 password） */ } }`

> 校验：手机号格式、密码长度、验证码、手机号未被注册。

#### POST `/auth/login` — 登录

| 入参 | 类型 |
|------|------|
| `phone` | string |
| `password` | string |

返回：`{ "token": "…", "user": { … } }`

#### POST `/auth/logout` — 退出 🔒

无入参。返回：`{ "userId": 1 }`

#### GET `/user/me` — 当前用户信息 🔒

返回：用户信息（**不含 `password` 字段**）

#### PUT `/user/me` — 修改个人资料 🔒

可更新字段：`nickname`、`avatar`、`phone`、`gender`、`bio`、`student_no`、`college`
返回：更新后的用户信息

#### GET `/user/products` — 我发布的商品 🔒

| Query | 类型 | 默认 | 说明 |
|-------|------|------|------|
| `keyword` | string | — | 标题模糊搜索 |
| `pageNum` | int | 1 | 页码 |
| `pageSize` | int | 5 | 每页条数 |

返回：分页结构，`records` 为 `Product[]`（装饰后）

#### GET `/addresses` — 收货地址列表 🔒

| Query | 类型 | 说明 |
|-------|------|------|
| `addressId` | int | 可选，指定则回填 `selected_id` |

返回（**非标准分页**）：
```json
{ "records": [ /* Address[] */ ], "selected_id": 1 }
```
> `selected_id` 优先级：query 指定 → 默认地址 → 第一条 → `0`

#### POST `/addresses` — 新增地址 🔒

| 入参 | 必填 | 说明 |
|------|------|------|
| `receiver_name` | ✅ | 收货人 |
| `phone` | ✅ | 手机号（校验格式） |
| `region` | ✅ | 区域/楼栋 |
| `detail` | ✅ | 详细地址 |
| `is_default` | — | 是否默认；用户首条地址自动为默认 |

返回：新建的 `Address`

#### PUT `/addresses/:id` — 修改地址 🔒

入参：`receiver_name` / `phone` / `region` / `detail` / `is_default`（均可选）
> 传 `is_default: true` 时，需把该用户其他地址的默认标记清除。

返回：更新后的 `Address`

#### DELETE `/addresses/:id` — 删除地址 🔒

返回：`{ "id": 1 }`
> 若删除的是默认地址，需自动把剩余第一条设为默认。

### B. 商品与分类

#### GET `/categories` — 分类列表

返回：`Category[]`（仅 `status=1`，按 `sort` 升序，含 `product_count`）

#### GET `/products` — 商品列表

| Query | 类型 | 默认 | 说明 |
|-------|------|------|------|
| `pageNum` | int | 1 | |
| `pageSize` | int | 12 | |
| `categoryId` | int | — | 分类筛选 |
| `keyword` | string | — | 标题或描述模糊匹配 |
| `minPrice` / `maxPrice` | number | — | 价格区间 |
| `sort` | string | `new` | `new` 最新 / `price_asc` / `price_desc` / `hot` 热度 |
| `sellerId` | int | — | 卖家筛选 |
| `status` | int | — | 不传时默认排除 `0`（下架） |

返回：分页结构，`records` 为 `Product[]`（装饰后）

#### GET `/products/:id` — 商品详情

| Query | 类型 | 说明 |
|-------|------|------|
| `withView` | string | 传 `'false'` 时不累加浏览量，否则 `view_count + 1` |

返回：`Product`（装饰后）。商品不存在返回业务错误。

#### POST `/products` — 发布商品 🔒

| 入参 | 必填 | 校验 |
|------|------|------|
| `title` | ✅ | 至少 4 个字 |
| `category_id` | ✅ | 必须存在 |
| `price` | ✅ | > 0 |
| `description` | ✅ | 至少 10 个字 |
| `original_price` | — | 默认取 `price` |
| `stock` | — | 默认 1 |
| `images` | — | 图片 URL 数组，为空时用默认封面 |
| `condition` | — | 默认 `九成新` |
| `location` | — | 默认 `校内可送达` |

返回：`Product`（装饰后），初始 `status = 1`

#### PUT `/products/:id` — 编辑商品 🔒

可更新字段：`title`、`description`、`category_id`、`price`、`original_price`、`stock`、`condition`、`location`、`images`
> 仅商品卖家本人可编辑，否则业务错误。

#### DELETE `/products/:id` — 下架商品 🔒

无入参。把 `status` 置 `0`。返回：`Product`（装饰后）
> 仅卖家本人可操作。

#### POST `/products/:id/relist` — 重新上架 🔒

无入参。把 `status` 置 `1`。返回：`Product`（装饰后）

#### POST `/favorites/:productId` — 收藏 🔒

返回：`{ "product_id": 1, "favorited": true }`（重复收藏幂等）

#### DELETE `/favorites/:productId` — 取消收藏 🔒

返回：`{ "product_id": 1, "favorited": false }`

#### GET `/favorites` — 收藏列表 🔒

| Query | 默认 |
|-------|------|
| `pageNum` | 1 |
| `pageSize` | 8 |

返回：分页结构 + `total_amount`（**全量收藏商品总价**，在分页前统计）
```json
{ "records": [ { "id": 1, "product_id": 3, "product": { /* Product */ } } ], "total": 10, "pageNum": 1, "pageSize": 8, "total_amount": 999.00 }
```

#### GET `/favorites/ids` — 收藏商品 ID 列表 🔒

返回：`number[]`，如 `[3, 5, 8]`

### D. 订单与交易

#### GET `/orders` — 订单列表 🔒

| Query | 类型 | 默认 | 说明 |
|-------|------|------|------|
| `role` | string | `buyer` | `buyer` 我买到的 / `seller` 我卖出的 |
| `status` | int/string | `all` | 传 `'all'` 或不传为全部 |
| `pageNum` | int | 1 | |
| `pageSize` | int | 5 | |

返回：分页结构 + `counts`（**基于全部数据统计，与筛选无关**）：
```json
{
  "records": [ /* Order[]（装饰后） */ ],
  "total": 12,
  "pageNum": 1,
  "pageSize": 5,
  "counts": { "all": 12, "0": 3, "1": 2, "2": 1, "3": 5, "4": 1 }
}
```

#### POST `/orders` — 创建订单 🔒

| 入参 | 类型 | 必填 | 说明 |
|------|------|------|------|
| `items` | array | ✅ | `[{ productId, quantity }]` |
| `addressId` | int | ✅ | 收货地址 |
| `remark` | string | — | 订单备注 |
| `cartIds` | array | — | 下单成功后需清理的购物车项 ID |

**业务规则（后端必须实现）**：
1. 不能购买**自己发布**的商品；
2. 商品必须 `status=1` 且 `stock > 0`，库存不足报错；
3. **一个订单只能包含同一卖家**的商品，否则报错；
4. 下单成功后**扣减库存**并累加 `sales_count`；库存为 0 时把 `status` 置 `2`；
5. **10 秒内同一用户对同一商品防重复下单**（Mock 用 Redis 锁 `order:lock:user:{userId}:product:{productId}`）；
6. 下单后通知买家与卖家（站内消息）；
7. 若传了 `cartIds`，删除对应用户的购物车项。

订单初始 `status = 0`，`order_no` 生成规则：`yyyyMMddHHmm` + 4 位随机数。
返回：`Order`（装饰后）

#### GET `/orders/:id` — 订单详情 🔒

返回：`Order`（装饰后）+ `address_text`
> 仅订单的买家或卖家可查看，否则报错。

#### POST `/orders/:id/pay` — 支付 🔒

| 入参 | 说明 |
|------|------|
| `payMethod` | 默认 `campus_card`；可选 `campus_card` / `wechat` / `alipay` |

**规则**：仅 `status=0` 可支付；**仅买家**可支付。成功后 `status=1`，写 `pay_method`、`pay_time`。
返回：`Order`（装饰后）

#### POST `/orders/:id/ship` — 发货 🔒

**规则**：仅 `status=1` 可发货。成功后 `status=2`。**真实业务中应由卖家操作**。
返回：`Order`（装饰后）

#### POST `/orders/:id/confirm` — 确认收货 🔒

**规则**：仅 `status=2`；**仅买家**可操作。成功后 `status=3`。
返回：`Order`（装饰后）

#### POST `/orders/:id/cancel` — 取消订单 🔒

**规则**：仅 `status ∈ {0,1}`；**仅买家**可操作。成功后 `status=4`，并**回滚库存**：
- `stock += quantity`；`sales_count -= quantity`；
- 若商品原 `status=2` 且回滚后 `stock > 0`，置回 `1`。

返回：`Order`（装饰后）

### E. 互动与消息

#### GET `/products/:id/comments` — 商品评论 🔒（实际可匿名访问）

| Query | 默认 |
|-------|------|
| `pageNum` | 1 |
| `pageSize` | 10 |

> **分页说明**：只对**顶层评论**分页，`total` 为顶层评论数；当前页每条顶层评论的**回复全部带上**（避免回复被拆到其他页）。

返回：`{ records: Comment[], total, pageNum, pageSize }`

#### POST `/comments` — 发表评论 🔒

#### GET `/messages` — 消息列表 🔒

# 个人联调（本地新建 .env.development.local，不入库）

## 六、最容易踩的 5 个坑（请后端重点确认）

| # | 坑 | 正确做法 |
|---|----|---------|
| 1 | 鉴权请求头写成 `Authorization` | 必须是 **`token`** |
| 2 | 返回裸对象或 `{ success, data }` | 必须是 **`{ code, message, data }`**，`code=200` 表成功 |
| 3 | 分页字段用 `list` / `items` / `rows` | 必须是 **`records`** |
| 4 | 401 返回 HTTP 401 且无响应体 | 需返回 **`code: 401`** 的 JSON，前端据此清登录态跳登录页 |
| 5 | 字段用驼峰 `productId` | 响应与请求体统一 **`snake_case`**（`product_id`） |
